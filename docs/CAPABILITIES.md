# Что умеют боты Vasyan (актуально по коду)

Мод собирается под **Minecraft 1.20.1 / Forge 47.2.0**. Ниже — только то,
что реально реализовано в коде, с примерами команд.

## Как общаться

- Нажми **K** — откроется панель справа (закрытие: **ESC** или **Ctrl+K**)
- Или в чате: `/vasyan tell <имя> <команда>`
- Спавн бота: `/vasyan spawn <имя>` (или в панели: `spawn Bob`)

## Действия, которые бот реально выполняет

| Что просить | Примеры | Параметры |
|---|---|---|
| **Копать руду** | «mine 20 iron ore», «накопай алмазов», «dig 10 coal» | `block` (iron/diamond/coal/gold/copper/redstone/emerald/…), `quantity` |
| **Построить здание** | «build a house», «построй замок», «make a tower» | `structure` (house/castle/tower/wall/platform/barn/modern/box), `blocks`, `dimensions` |
| **Поставить блок** | «place a torch here», «put cobblestone at 100 64 -200» | `block`, `x`, `y`, `z` |
| **Атаковать** | «attack that creeper», «kill zombies», «defend me» | `target` (hostile — любые враждебные) |
| **Следовать за игроком** | «follow me» | `player` |
| **Путь к точке** | «go to 100 64 -200» | `x`, `y`, `z` |
| **Собрать ресурсы** | «gather wood», «collect stone» | `resource`, `quantity` |
| **Телепорт к игроку** | «приди ко мне», «teleport to me» | `player` (или `USE_NEARBY_PLAYER_NAME`) |
| **Стоять на месте** | «стой», «замри», «wait» | — |
| **Craft (НЕ РАБОТАЕТ)** | «craft a pickaxe» | вернёт «Crafting not yet implemented» |

## Что важно знать

1. **Craft не работает** — в коде заглушка, всегда возвращает ошибку. Не тратьте на него время.
2. **Одно действие за раз** — бот выполняет задачи последовательно, пока не закончит (потом вернётся к «следованию за игроком» в простое).
3. **Бот неуязвим** (invulnerable) и может летать — специально, чтобы не умирал при выполнении задач.
4. **«mine»/«gather» — маршрутизированный поиск, БЕЗ туннелей**: бот бежит по земле по спирали станций вокруг точки старта
   (радиус/таймаут в конфиге `[gather]`, дефолт 32 блока/60 сек), на каждой станции сканирует зрением и добывает
   ТОЛЬКО видимые блоки. Руду/дерево добывает всегда (инструмент в наличии виртуально). Туннелей не копает.
   **Деревья валит целиком**: поднимается по стволу на столбе из реальных блоков инвентаря (земля/камень), срубает
   все брёвна включая ветки (джунглевые 2×2 и модовые гиганты — до 200 логов/64 блоков высоты), спускается,
   разбирая столб — ноль мусора в ландшафте. Листья опадают сами, дроп подбирает вакуум. При пустом инвентаре
   блоков — сначала добывает землю, потом продолжает валку.
5. **Постройки процедурные**: house/castle/tower/wall/platform/barn/modern/box генерируются алгоритмом. NBT-шаблоны (oldhouse/powerplant) в ресурсах отсутствуют — не работают.
6. **Несколько ботов** могут строить один объект совместно (деление на секторы).
7. **Память только на сессию** — после рестарта мира боты забывают всё.
8. **Голосовые команды (клавиша V, push-to-talk)**: запись с микрофона (Java Sound, 16kHz WAV) → сервер транскрибирует через ЛЮБОЕ OpenAI-совместимое STT API (эндпоинт/ключ/модель/язык — конфиг `[voice]`) → команда раздаётся ботам как из чата K. «● REC» в панели — индикатор записи.
9. **Имена ботов**: матчинг терпит русскую транскрипцию латинских имён («алекс»→Alex, «стиви»→Vasyan — транслит + словарь); кириллические имена ботов работают.
   **Правила имени** (`/vasyan spawn <имя>`): буквы (любого алфавита, включая кириллицу), цифры и символы `_ - . +`. Пробелы, кавычки и прочие символы запрещены; имя в кавычках тоже валидируется по этому набору. Если Vasyan создан раньше с именем вне набора — к нему больше нельзя обратиться командой, пересоздайте с допустимым именем.
10. **Навигация планирует копание/мосты/столбы напрямую** (этап 0.6 P2): маршрут считается A* по рёбрам WALK / DIG / PLACE / PILLAR_UP — бот сам прокапывается сквозь стену в 1–2 блока, наводит мост через провал глубже `maxDropDown` и ставит столб на короткий обрыв, вместо того чтобы застревать. План строится только из блоков, разрешённых `scaffoldWhitelist`, — то, что бот реально поставит. Аварийная «лестница» восстановления (dig → scaffold → hop-teleport) остаётся только запасным планом при застревании. Ключи секции `[navigation]` конфига (дефолты): `digCost` = 4, `placeCost` = 4, `liquidCost` = 20 (надбавка к WALK-шагу, ведущему в клетку с водой или лавой), `entityCost` = 8 (**зарезервировано, пока не влияет** на стоимость маршрута), `maxDropDown` = 3, `digHardnessFactor` = 1.0, `scaffoldWhitelist` = [minecraft:dirt, minecraft:cobblestone], `thinkTimeoutMs` = 2000, `tickTimeoutMs` = 10, `searchRadius` = 64, `replanCheckIntervalTicks` = 10 (раз в этот интервал бот проверяет живость маршрута: непробиваемая клетка коридора копания или занятая клетка моста/столба заставляют перепланировать).

## Если бот не выполняет команду

1. `/vasyan providers` — проверить провайдера, модель, наличие ключа, health (ONLINE/UNREACHABLE)
2. `/vasyan debug` — показать: конфиг LLM, состояние каждого бота (idle/planning/executing) и
   **последние 20 событий**: команда → ответ LLM → разбор → запуск действия → результат
3. `/vasyan tp <имя|all>` — мгновенный телепорт бота (или всех ботов) к безопасной точке рядом с игроком.
   Использует переиспользуемый API `VasyanEntity.teleportToPlayer()` — тот же механизм, что Этап 3
   задействует для авто-возврата при полном инвентаре; `teleportToPos()` — задел под телепорт
   на точки (шахта, дом). В другом измерении — внятная ошибка.
   **Из чата панели K** боты понимают действие `teleport`: «все телепортируйтесь ко мне»,
   «alex телепорт ко мне», «come to me» (панель сама адресует «all …»/«все …» всем ботам —
   раздача через сервер `tell all`).
4. **stay/стой** — полная остановка бота до следующей команды: «стой», «замри», «wait», «stop»
   (обрабатывается детерминированно, без LLM; `/vasyan stop <имя>` — то же самое). После остановки
   бот не следует за игроком (idle-follow отключён); любая новая команда его «будит».
5. Типовые причины по событиям:
   - `LLM_ERROR` — сеть/ключ/провайдер недоступен
   - `PARSE FAILED` — LLM вернул не-JSON (обычно лечится `jsonMode = true` в конфиге)
   - `PARSE ok, 0 tasks` — LLM не понял, что делать; переформулируйте команду
   - `NO_ACTION` — LLM выдал действие, которого нет в реестре (см. таблицу выше)
   - `ACTION_FAIL` — действие началось, но не удалось (например, руды нет рядом)

## Ограничения LLM

- Качество зависит от модели: для opencode-go `deepseek-v4-flash` — быстро и дёшево;
  `kimi-k3`, `glm-5.2` — умнее, но дороже/медленнее
- Маленькие локальные модели (ollama 7-8B) могут путать формат JSON — включайте `jsonMode`
- Бот «думает» через API — без интернета/ключа работает только fallback-режим (простые
  шаблоны: mine/build/attack/follow по ключевым словам)
